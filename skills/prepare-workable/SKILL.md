# Prepare a Workable application

Use only an individually identified `/company/j/TOKEN/apply` application. The registry must enable preparation; recognizing Workable does not enable unsupported widgets or final submission. Reuse the exact owned draft tab and serialize CLI operations. Preserve the submission guard and all other drafts.

Use the selected SDE or ML booklet catalog. A file input inside `[data-ui="resume"]` owns the resume; `[data-ui="avatar"]` is a photo upload and must not receive it. Native file receipts bind the PDF bytes and exact input, and invalidate when the native input changes. Workable's cover-letter field can be text; a PDF path is not cover-letter prose.

Native controls must belong to the observed application form. Preserve full question wording, requiredness and control ownership. Inspect native radio/select choices and commit an exact approved choice with trusted native input; an unfamiliar checkbox needs its own approved answer. Blank optional answers can remain blank.

Education and Experience use Add, Update and Edit editors, with repeated `summary` ids. Verify the active editor and each saved record independently. Never write the employment summary into the global profile summary. Dates come from verified original records; a future graduation date is not a completed degree. Unsupported date widgets or saved-record ownership require a mechanical handoff, not a repeated factual question.

Preparation stops at a retained review packet. Required unknown facts enter the question ledger. Authentication uses Google SSO; another method needs a specific user exception. A challenge or ambiguous control pauses this job. Final submission belongs only to a separately authorized, reviewed submission runtime with fresh retained-answer checks and a confirmed receipt.

## Complete question review

Keep every observed question, including blank optional fields and saved profile
rows, in `review_inventory`. Confirm a stable final observation before marking
the inventory complete. A required-only audit does not establish completeness.
Separate substantive written prompts from voluntary disclosures and
communications. Use grounded selected-role facts for permitted prose; an
explicit “no AI text” instruction requires candidate wording in the question
ledger and portal. Preserve the original label and requiredness. Every optional
blank requires an explicit portal Leave Blank acknowledgment; submission also
requires approval of the exact packet.
